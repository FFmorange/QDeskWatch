# 项目文件检索

先读结构文档，再精准定位当前项目中的文件与模块。

## 工作流程

1. 先读取 `docs/project-file-structure.md`。
2. 先判断当前需求最接近仓库中的哪一块区域。
3. 使用 `rg --files` 或 `rg` 缩小候选文件范围。
4. 只打开最相关的文件，并确认真正的改动落点。
5. 输出具体路径，并为每个关键路径补一条简短原因。

## 检索规则

- 把 `docs/project-file-structure.md` 视为仓库地图，在进行大范围搜索前先读它。
- 文件发现优先用 `rg --files`，文本检索优先用 `rg`。
- 将 `.qtcreator/` 视为 IDE 本地配置，将 `build/` 视为编译产物；除非用户明确要求，否则不要深入检查。
- 将 `install/` 与 `plugins/market/` 优先视为生成物或分发落点，而不是主源码真值来源。
- 如果结构文档与仓库当前状态不一致，以当前仓库实际文件为准，并指出文档可能需要同步更新。

## 输出要求

- 返回独立、明确的文件路径，不只给目录级猜测。
- 如果有多个相关路径，先指出主要改动落点，再列补充路径。
- 如果请求同时跨越 QML、C++ 和插件边界，在开始编辑前要明确说出来。
